## 0. 一句話講清楚(電梯簡報)

> 我們做了一個**六代理 LLM 系統**,自動把課綱書目變成圖書館採購建議。原本以為瓶頸是 LLM 幻覺(亂編書),但四個實驗發現**幻覺其實極低(0–1.4%),真正瓶頸是驗證階段**——驗證器把書配錯權威記錄、以及查詢來源覆蓋不足。所以多代理架構的價值不在防幻覺,而在**可稽核**和**抓細節錯誤**。

**為什麼反直覺**:大家做 RAG / agent 都假設 LLM 會幻覺要外部防範,但我們量出來 LLM 生成很可靠,問題在**後面配對那一關**,不是生成那一關。

**現狀**:已轉成 IMCOM 的 IEEE 格式、6 頁、投第二輪(截稿 10/15)。

## 2. TABLE 1 — 架構對照(最核心)

| Metric | A (pure LLM) | B (LLM+tool) | C (system) |
|---|---|---|---|
| Correctness | 98.6% (69/70) | 100% (70/70) | **80.0% (28/35)** |
| 95% CI | 92.3–99.7% | 94.8–100% | 64.1–90.0% |
| Hallucination | 0% | 1.4% | — |
| 95% CI | 0–5.2% | 0.3–7.7% | — |

- **A** = 純 LLM 無工具;**B** = LLM + 查證工具(自己決定要不要用);**C** = 完整系統(強制驗證配對)
- **括號** = 分子/分母(如 69/70 = 70 本對 69 本)
- **C 幻覺是「—」**:C 的 ISBN 由 API 決定,結構上不可能幻覺
- **故事**:A/B 生成很準(98.6–100%)、幻覺極低;但 C 掉到 80%,掉的 20% **全來自驗證器配錯** → 瓶頸在驗證

### 老師必問
- **「C 分母為何是 35 不是 70?」** → C 只計入「有走到驗證器配對階段」的書,所以 35 本(註解有寫)。
- **「C 比純 LLM 低,系統不是更爛?」** → 不是。C 評端到端(生成+配對),A/B 只評書名。且只有 C 有 ISBN、可追溯、能採購;A/B 書名對但沒 ISBN、不能用。C 低正證明瓶頸在驗證。
- **「A、B 幻覺率有差嗎(0% vs 1.4%)?」**(陷阱)→ **CI 重疊,統計上分不出差異,不能說 A 比 B 好。**
- **🔴「B 100% 和 C 80% 差 20 分,你卻說 B/C『表現相近』,矛盾?」**(高頻陷阱)→ 老師抓到真問題,誠實承認。①「相近」講的**不是 correctness 數字**,是指「B 靠 LLM 自主查證、C 靠強制查證,兩者**防錯行為**相近——B 沒因偷懶不查而出錯」。②100% vs 80% **根本不能比**:B 評書名、C 評配對後記錄,樣本也不同(70 vs 35)。③這正是審稿人批的「不對等比較」,**我們正在用 paired evaluation 重做**(同一批書追蹤生成→配對),做完就不會有這矛盾。→ 論文 IV.E「perform comparably」用詞要改成「in error prevention the two are comparable」。

## 2b. B 的 `search_book` 工具是什麼

**是什麼**:給 LLM 呼叫的**函式工具**(function calling)。輸入書名+作者,去查真實書目庫確認書存不存在、拿回正確書名/作者/ISBN;找到回權威記錄,查無回 `{found: False}`。

**查哪些庫(依語言自動分派)**:中文→**NCL/NBINet**;英文→先 **LOC**、查不到再 **Google Books**。**與系統 Validator 用同一批來源**(刻意設計)。

**B 和 C 的差別(重點)**:
| | 誰決定查證 | 強制? |
|---|---|---|
| B | **LLM 自己決定**要不要呼叫、信不信結果(多輪迴圈最多6輪) | ❌ 不強制,可不查 |
| C | **架構強制**每本都經 Validator 查證配對 | ✅ 100% 覆蓋 |

**證明什麼**:B 靠 LLM 自律用工具、C 架構寫死。結果 B 很勤勞地呼叫(高呼叫率),沒發生「偷懶不查而出錯」→ 所以「強制驗證較優」是**架構論證、非實驗證實**(B 剛好都查了才相近)。C 的優勢(保證覆蓋+可稽核)要在對抗性/大規模才顯現 = future work。

### 老師必問
- **「B 工具和 C 驗證器有何不同?」** → 後端來源一樣,差在 B 由 LLM 自主決定、C 架構強制。
- **「後端一樣、結果相近,那 C 有何價值?」** → B 沒程序保證(這次都查是運氣),C 把驗證寫進流程,保證 100% 覆蓋+可稽核,公帑採購場景重要。誠實講是架構論證非實驗證實。
- **「search_book 是現成 API?」** → 我們包的函式,底層呼叫 NCL/LOC/Google Books,依語言分派,跟 Validator 同來源。

## 3. TABLE 2 — 失敗成因診斷

| Failure cause | English (49) | Chinese (100) |
|---|---|---|
| T1 recovered-after-fix | 12.2% (6) | 33.0% (33) |
| T2 unresolved query defect | 26.5% (13) | 17.0% (17) |
| T3 coverage gap | 61.2% (30) | 50.0% (50) |
| **Query-related (T1+T2)** | **38.8% (19)** | **50.0% (50)** |

- **T1**:正規化(去卷號/副標)後重查就找到 → 本來就可修
- **T2**:正規化後仍沒找到,但寬鬆查詢找得到相似書 → 書存在、精確比對抓不到 → 也是查詢問題
- **T3**:連寬鬆查詢都找不到 → 來源沒收錄 → 沒救,只能擴充來源
- **T1+T2 = 查詢相關** = 改善查詢就能解決的比例

**故事(核心洞察)**:中英文失敗結構不同 →
- 英文:六成覆蓋缺口(T3=61.2%)→ 要**擴充來源**
- 中文:一半查詢相關(50%),33% 正規化就直接救回 → **投資查詢正規化 CP 值最高**

### 英文 49 / 中文 100 怎麼決定的
- **英文 49 = 全量**:英文失敗書總共只有 49 本,全跑(最準,無抽樣誤差)
- **中文 100 = 抽樣**:中文失敗書母體 481 本,太多,用固定種子(seed 42)隨機抽 100 本
- **為何不對稱**:純粹數量差異——英文少全跑、中文多抽樣

### 老師必問
- **「為何英文全量、中文抽樣?」** → 英文只 49 本全跑;中文 481 本太多,隨機抽 100 代表,固定種子可重現。
- **「中文抽 100/481 代表性夠嗎?」**(誠實)→ 約 21% 抽樣,隨機+固定種子有代表性,但樣本有限,結果講成 observational 不宣稱顯著。這是 limitation。
- **「中文 T3=50% 準嗎?」** → 上限估計。中文用 NCL 主探針+Google 輔助,單一來源覆蓋都不全,真實覆蓋缺口可能更低。
- **「33% 救回是真實裝進系統嗎?」** → 是離線 replay 估計(套正規化重查),非重跑整條 pipeline。另外人工複核 12 本判定可救回的書,全部確認救回。
- **「兩欄百分比能直接比嗎?」** → 我們看的是**結構差異**(英文以覆蓋缺口為主 vs 中文以查詢缺陷為主),不是比精確數值。

## 4b. 回饋迴路(Validator→Discoverer)詳解

**是什麼**:在直線 pipeline 上加一條 Validator→Discoverer 條件邊(LangGraph 實作)。AI 推薦的書驗證失敗時,失敗訊號送回 Discoverer 重推另一本,形成自我修正閉環。= 標題的 "Verification-Driven Self-Correction"。

**執行流程(=Fig.1 真實案例)**:
無書單課「Media & Cultural Techniques」→ Discoverer 推《Technics and Time, 1》→ Validator: not_found(卷號「,1」破壞比對)→ 訊號送回 → 重推《Cultural Techniques》等 → verified ✅

**關鍵機制**:
- 只對 **AI 推薦的書**作用,不動 Parser 抽的課綱書(課綱書是指定的,查不到≠書錯,換掉=竄改書單)
- 迭代上限 = 2(避免無限迴圈)
- 舊記錄不刪,用 `superseded_by_iteration` 標記保留(可追溯),下游查詢排除
- 計數器由 Validator 遞增、只由路由函式讀 → 保證終止
- 排除 API 配額耗盡的暫時性失敗(那不是書不存在)

**實驗3結果(背)**:50 門課、249 本 AI 推薦書;首驗成功率 **99.2%**(只 2 本失敗);2 本都救回但整體只 **+0.8pp**;2 本成因不同(一查詢缺陷、一覆蓋缺口)。

**🔴 核心洞察:效益上限取決於失敗成因**
迴路能救「模型推薦錯」(換一本就好),救不了「書存在但來源沒收錄」(換書只是繞過盲點)。因首驗已 99.2%,可救空間本來就小 → **呼應主軸:生成太可靠,自我修正沒多少事可做**。

### 老師必問(回饋迴路)
- **「只 2 case、+0.8pp 也算貢獻?」**(最尖銳)→ 沒誇大,論文講它 illustrative 非 conclusive。「沒什麼可救」本身有意義:生成太可靠(99.2%),修正空間小,呼應反直覺主軸。且我們誠實界定「效益上限取決於失敗成因」,是一般性結論不只 2 case。
- **「那為何還做?」**→ 設計時假設生成會常錯、迴路會有用(直覺),實驗後才發現生成可靠。價值在:(1) 把直線 pipeline 變真正的多代理協作(一 agent 失敗訊號改變另一 agent 行為);(2) 量化了自我修正的邊界。
- **「怎麼保證會停?」**→ 迭代上限 2 + 計數器由 Validator 遞增不被重置。
- **「為何不對課綱抽取書重推?」**→ 課綱書是指定的,失敗可能只是來源沒收錄,換掉=竄改書單。
- **「怎麼隔離 LLM 隨機性?」**→ no-loop / with-loop 共用同一次初始推薦當起點,差異純來自迴路。

**開會策略**:這是三貢獻中最弱的(+0.8pp、2 case)。若老師覺得弱,別硬撐 → 「我們也覺得效益有限,論文誠實反映。老師建議強化(擴大樣本)還是降為次要發現?」把決定權交回老師。

## 5. 95% CI 是什麼(老師愛考)

- **CI = 信賴區間**。樣本只 70 本,量到 98.6% 有抽樣誤差,CI 表示「真值有 95% 信心落在這範圍」(92.3–99.7%)。
- **樣本越小 CI 越寬** → 所以我們一直講「observational、不宣稱顯著」。
- **用 Wilson interval**:因為有 0%、100% 極端比例,一般 Wald 公式在極端值失效,Wilson 專門處理。
- **CI 重疊 = 分不出差異**(A、B 幻覺率就是這樣)。

## 6. 三大高殺傷力問題 + 答法

### 🔴 Q:「幻覺率低是不是任務太簡單(抄課綱當然不錯)?」
> 按來源拆:**抽取類**(有書單=抄)30 本、**AI推薦類**(無書單=LLM自己想)40 本。**推薦類 40 本幻覺 0%**,唯一幻覺反而在抽取類。所以低幻覺不是任務簡單——最需要生成的推薦情境反而零幻覺。
> (追問樣本少)→ 對,CI 0–8.8%,講成「觀察到 0 幻覺」不是「證明不會幻覺」。

### 🔴 Q:「只測一個模型(GPT-5.5),能說『LLM』幻覺低嗎?」
> 誠實:是最大 limitation 之一,結論嚴格說是「GPT-5.5 在此任務」,跨模型泛化是 future work。
> 加分:但**架構論點**不依賴特定模型——只要生成夠可靠,瓶頸就轉到驗證,這結構性發現通用。

### 🟡 Q:「回饋迴路只有 2 個 case,算 evaluation 嗎?」
> 首驗成功率已 99.2%,只 2 個觸發。沒誇大,論文講它 illustrative 非 conclusive。這「沒什麼可救」本身呼應主軸——生成可靠所以修正空間小。
> (若說貢獻弱)→ 可擴大無書單課程抽樣拿更多 case(future work),或降級為「誠實發現」。**老師覺得哪個好?**
